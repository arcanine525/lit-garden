1 passed (18.5s, 14.6s test body) before adding the cancel assertion.

- Only the owner teacher and the author student can read or reply to a
  current comment. A different student in the same class and an admin
  cannot read the thread. The test addresses a specific submission and
  comment and verifies that the overall comment has its own empty thread.
- The teacher saves an edit and starts republishing. The provider holds
  the upload response after creating the publication candidate. The author
  replies to the old, still-current comment and commits first. The final
  publication transaction rejects COMMENT_LOCKED, leaves the current ID
  unchanged, and marks the candidate as an orphan. The retained response
  freezes the comment. The teacher restores the original published text
  and republishes with the same comment identity and conversation.
- A reply file is created and the fake Drive returns 504. Explicit retry
  with the same key and body keeps the same file ID, adds one message and
  one notification, and supports replay. Canceling a separate ambiguous
  reply clears its pin and orphans its file without adding a message.
- Three messages are written as individual Markdown files, read back via
  the authenticated adapter with original order and authors, and attributed
  to the correct comment. A database attempt to edit a sent message fails.
  The closed assignment still permits replies. Archive and student removal
  preserve the existing thread in read-only mode for the student.

The test uses real local application sessions and PostgreSQL. File writes,
read-backs and delayed responses use the HTTP fake Drive. The append-only
DB triggers are restored within the test's scoped cleanup transaction.
Live Google Drive was outside this verification.
