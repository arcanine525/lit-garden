$ PLAYWRIGHT_CHANNEL=chrome npm run test:e2e -- classes.spec.mjs
1 passed. The test creates and edits a class in the browser, provisions one
student individually and checks valid, invalid, repeated and existing rows in
a UTF-8 CSV fixture. An existing username keeps its original password and
membership. The second teacher uses the original identity via a join request.
Before approval the second class has no membership or assignment recipient for
that student. The wrong teacher cannot approve; the owner can.

The CSV retry test launches a second instance of the production build, uses
real Keycloak and pauses the local DB transaction on membership insertion.
The test waits for the recorded Keycloak subject and the blocked transaction,
kills the second app process, and verifies that membership did not commit.
Retry with the same batch and row returns the same account subject, exactly
one membership, and a one-time password. A repeat returns no password.

CSV refers to an existing class by name and school year. The source stays
in the browser for per-row retry. Before approval the membership and recipient
preconditions for content access are absent. T07 checks the PostgreSQL access
predicates. HTTP prompt and submission paths are covered as T17 and T20 land.
No live Google service was used.
